# Chrome Reading List: Why Nobody Uses It

## Post Packet

- **Canonical keyword**: `reading list chrome`
- **Cluster volume**: ~1,000/mo from cached DataForSEO.
- **SERP gap**: Top results explain how to find, add, pin, or disable Chrome Reading List. They do not explain why a built-in read-later surface still fails the save-vs-read job.
- **Reader intent**: "Where did Chrome Reading List go?", "how do I use it?", or "is this the same as bookmarks?"
- **Totem fit**: Totem is not a generic web read-later app. The honest bridge is surface design: Chrome Reading List hides saved pages in a side panel; Totem puts saved X bookmarks on the new tab.

## Fragments

- Chrome Reading List is not a bad feature. It is just too quiet.
- The official path is already a clue: More -> Bookmarks and lists -> Reading list -> Show reading list.
- A feature that needs a "where did it go?" SERP has a surface problem.
- Reading List stores URLs and read/unread status. It does not decide what deserves your next five minutes.
- A return path has to interrupt the forgetting loop.
- If the thing you save lives inside X, a Chrome page saver is the wrong object.
- The right question is not "does Chrome have a reading list?" It does. The question is where the list appears when you are deciding what to open next.

## Beat Map

1. Answer the literal query: where Chrome Reading List is and how to add a page.
2. Define what it actually is: side-panel list of pages with read/unread/delete behavior.
3. Explain why it fails for many people: hidden path, weak return surface, no reading loop.
4. Separate Reading List from Bookmarks and Reading Mode.
5. Say when it is enough.
6. Say when to use a dedicated read-later/bookmark tool.
7. Honest Totem CTA: only for X bookmarks, not the whole web.
