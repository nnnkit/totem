## Fragments

- A Twitter bookmark manager is usually a proxy request. The reader rarely wants "a manager." They want one of: find a saved post, export the library, read threads without X, stop forgetting, sync to Notion, delete junk, or feed saved context into AI.
- X already solves the save gesture. X's help page says Bookmarks save posts in a timeline you can revisit. The problem starts after that.
- Totem should not claim to beat Dewey at cloud sync or TweetSmash at digests. It wins when the bookmark is a reading queue and the next-tab surface matters.
- Dewey is the "central dashboard" answer: many sources, folders, tags, export, Notion/RSS/share. It is a place.
- TweetSmash is the "make me read this later by email or workflow" answer.
- Twillot is closer to a Twitter data console: bookmarks, likes, tweets, media, replies, AI classification, export, clear.
- XBookmark is interesting because it is free, local, open-source framed, and small. It belongs as a lean/local pick, with a caveat about maturity.
- ContextBolt is the new AI-native entrant: semantic search, topic clustering, MCP. It also sends bookmark text for AI processing, so it is not the same privacy posture as local-only tools.
- Circleboom deserves inclusion because it is prominent, official-enterprise-developer framed, and good for bulk cleanup/filter/export. It is not a reading product.
- One-click exporters and userscripts are not bookmark managers. They are file tools. They belong in a note, not the main leaderboard.
- We need a comparison table that makes "where Totem loses" obvious.
- The CTA can be small: if bookmarks are a reading queue, put them on the new tab.

## Beat Map

Reader problem: "I saved too many posts on X and the native bookmark tab is not enough."

Thesis: There is no best Twitter bookmark manager. There is the right shape for the next job: read, search, export, organize, sync, clean, or feed AI.

1. Open with the job split. X already saves; third-party tools compete on what happens after the save.
2. Give the short decision table immediately so searchers get an answer above the fold.
3. Explain the comparison test: surface, search, export depth, data location, account model, reading vs organizing.
4. Cover the seven main picks, each with screenshot, best-for, strengths, losses.
5. Handle native X, one-click exporters, and userscripts as "not managers, but sometimes enough."
6. End with a condensed comparison table and a small Totem CTA.
7. Add footnotes and internal links.

Where Totem appears: first in the job table and first pick, with explicit disclosure. The post remains useful because it recommends competitors for jobs Totem does not try to own.

What the post does not cover: generic Chrome bookmark managers, full read-it-later apps, generic Twitter/X productivity extensions, or account-growth tools.
