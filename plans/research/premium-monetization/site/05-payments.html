Payment Gateway — The Decision

Native Chrome Web Store payments died Feb 1, 2021, so an external processor is mandatory. The choice is not just "who takes the smallest cut" — it is which option keeps Totem server-free, privacy-safe, and resilient to provider outages.

Recommendation

Lemon Squeezy as merchant-of-record (primary), Polar as the cost-optimized alternative — and use the provider's license-key API for verification: validate the key online once at activation, cache the result locally, fail open, with a generous device limit.

Why MoR, not ExtPay

ExtPay is the fastest to wire and the most extension-native, but it (a) is not a merchant of record, so you still owe VAT in every country, and (b) makes every paid check a live getUser() call to extensionpay.com with no documented offline cache — so a network failure can throw on a routine launch. The MoR's license API is better on both axes: it removes the tax burden, and you call validate once at activation, then run from a local cache and only re-check occasionally in the background. You verify online, but you don't depend on the network being up on every launch.

Why online validate (not a fully-offline signed key)

We deliberately accept one online check. It is the simplest path, it is what makes device management possible (something has to count activations), and it lets the provider revoke a refunded or charged-back key. MV3 allows it cleanly: validating a key returns JSON data, not remote code. The cost — a host permission and a reworded store description — is small. We do not ship an on-device signature verifier, a license-signing vendor, or a private signing key; the provider issues and validates the key.

The rule that keeps it resilient — cache + fail-open

Validate online at activation → write isPro to CS_ENTITLEMENT → read from that cache on every launch. Re-validate quietly in the background (e.g. weekly) to catch refunds. If a re-check can't reach the network, keep Pro on (fail-open, with a grace window) — never revoke a paying user because their Wi-Fi blipped or the provider had a hiccup. "Online verification" means check when we can, trust the saved answer otherwise — not gate every launch on a live call.

Multi-device activation

A purely offline key can't be counted (nothing knows how many browsers hold it). Because verification is online, the provider is that shared counter: set a generous activation limit (~5), expose activate / deactivate so a user can free a slot from the customer portal (the fix for the reinstall-burns-a-slot complaint), and send a device id on activate. An unlimited limit ("use on all your browsers") is a defensible zero-friction alternative for a $19 honest-audience tool — you just accept that a key could be shared, the same way the open-source build can already be patched.

BRAND PROMISE, PRECISELY
Not "works offline, nothing can shut down," but the truthful version: no Totem server to run — the provider handles checkout, tax, and licensing; your bookmarks never leave your device; Pro is verified by a quick online check, then cached and read locally. Cached entitlements ride out a short provider outage — relevant given the Lemon-Squeezy→Stripe transition watch-item.

The honest stance (publish it — it converts for this audience)

Open-source + client-side means a determined user can patch out the check. Don't fight it. Ship this copy in the README and the upgrade screen:

Totem is open source. You could patch out the Pro check — the code is right there. We're not going to fight you with DRM that makes the app worse for everyone. Pro is $19 once; it funds the export, search, and deleted-tweet preservation work. If it's useful, buy it. If you genuinely can't, the free tier is fully functional forever. - Totem upgrade screen / README

For a $19 lifetime tool, the cracker's "service" (untrusted patched build, re-patch every update, no support) is worse than paying. For the privacy/HN/self-hosted audience, the absence of DRM is a trust signal, not a weakness. (Gabe Newell's "piracy is a service problem" — sourced in rs-license-arch.md.)
