This document synthesizes a nine-agent deep dive of the Totem codebase and the 2026 payments/extension market, plus an adversarial verification pass. The appendices reproduce the underlying research records.

Method

Five agents read the codebase along independent seams (data & sync, features & export, build & release, site & distribution, UI state & upsell). Four agents researched the market (payments, license architecture, recent discourse, Chrome Web Store policy & UX). A final reviewer adversarially re-checked the load-bearing code claims against the live repository and red-teamed the strategy. The nine raw reports are condensed in Appendices A–I; the verification pass is Chapter 11.

B. Glossary

MoR (Merchant of Record) — a payment provider that becomes the legal seller and remits global VAT/GST on your behalf (Lemon Squeezy, Polar, Gumroad). Removes the tax-registration burden from a solo developer.

MV3 — Chrome Manifest V3. Bans remotely-hosted code but allows fetching remote data; pure local crypto verification is trivially compliant.

Entitlement — the device-global fact "this install is Pro." Stored authoritatively in CS_ENTITLEMENT (service-worker-owned chrome.storage.local), independent of account or reset.

Ed25519 signed key — a license token signed with a private key the buyer never sees and verified on-device with an embedded public key via @noble/ed25519. Enables offline, no-phone-home verification.

Grandfathering — granting existing users full features free, forever, so the paywall only ever applies to new installs. The primary backlash mitigation.

Hydration — Totem's existing engine that fetches and caches tweet detail, already classifying deleted/protected tweets — the basis of the "deleted-tweet preservation" Pro feature.

CWS — Chrome Web Store. Native in-extension payments were removed Feb 1, 2021; an external processor is mandatory.
