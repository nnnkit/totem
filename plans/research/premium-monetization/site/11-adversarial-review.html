Adversarial Review — What the Red-Team Caught

Before this plan was finalized, an independent adversarial reviewer re-checked every load-bearing code claim against the live repository and red-teamed the strategy. It confirmed most of the architecture and forced three concrete corrections — all already folded into the chapters above. This chapter records what it found, so the reasoning is auditable.

Confirmed against the live code

  • Entitlement storage — src/service-worker/storage-keys-sw.ts exists and the single-writer invariant is enforced by src/lib/__tests__/storage-invariants.test.ts. (Caveat: the test arrays are hardcoded, so a new key must also be added there to be enforced.)
  • Reactive channel — the CS_RUNTIME_STATE_V2 → onChanged → applyRuntimeSnapshot path is real; an added snapshot field propagates to every tab.
  • Reset survival — src/lib/reset.ts has explicit key lists and already preserves auth keys deliberately; CS_ENTITLEMENT can be kept out of them.
  • Deleted-tweet preservation — TweetDetailCache in src/types/index.ts already carries detailsStatus/unavailableReason; the hydration store already classifies deleted vs protected. The "already built" claim holds.
  • Build pins & static site — scripts/verify-cws-featured-readiness.mjs really hard-pins permissions, hosts, description, and screenshots; apps/site/astro.config.mjs is output:"static" with no adapter, so it cannot host a license endpoint.

Corrected before shipping

1 · Export is not a single gate

The bulk-ZIP path concentrates at ExportModal.tsx:64, but src/components/BookmarkReader.tsx:313-352 has four independent per-article egress handlers (copy-Markdown, copy-for-agent, download .md, print/PDF) that bypass ExportModal entirely. The "copy stays free as a teaser" idea is therefore a slow full-library leak — a knowing trade-off, not an oversight. All four handlers must be gated; the file is BookmarkReader.tsx, not TweetContent.tsx.

2 · The Ed25519 / @noble SHA-512 build trap

The standard ed25519 wiring snippet imports { sha512 } from '@noble/hashes/sha512', which does not resolve against @noble/hashes 2.x (neither /sha512 nor /sha2 is an exported subpath). The repo pins 2.2.0. Use import { sha512 } from '@noble/hashes/sha2.js' (the .js suffix is required) and register ed.etc.sha512Sync at service-worker startup before any verify call.

3 · Grandfathering by install-reason misfires

chrome.runtime.onInstalled with reason === "install" fires for uninstall→reinstall and new-machine cases, so reason alone strips grandfathered status from exactly the engaged users it is meant to protect. Add a secondary heuristic that also runs on install: treat a non-empty bookmarks IndexedDB store (or a pre-Pro settings key) as proof of an existing user.

Bottom line
The architecture survived scrutiny; the three corrections are mechanical, not structural. The plan ships with them already incorporated.
