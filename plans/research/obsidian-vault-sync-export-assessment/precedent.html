What the best read-it-later tools actually do

Readwise, Matter, and Raindrop converge on one shape: an idempotent, ID-keyed write loop that owns its own subfolder and never deletes what it didn't create. Omnivore shows the failure mode Totem must avoid.

The pattern to copy

Across the durable tools, the write loop is the same. Totem should adopt it wholesale.

The idempotent loop
  • Each item maps to a stable file path keyed by a durable ID — the same bookmark always lands on the same note.
  • Re-syncing updates in place instead of duplicating; the ID, not the title, is the key.
  • The tool writes into its own subfolder and treats everything outside it as off-limits.
  • It never deletes user files — unsynced items are left alone, not pruned.
What rides in the note
  • YAML front matter with typed metadata that Obsidian Properties and Dataview can query.
  • Highlights and notes rendered into the body, often as Obsidian callouts.
  • A clear marker that the file is tool-managed, so manual edits and regeneration don't collide.
  • Self-contained, atomic files — one note per item, no shared mutable index that races.

Totem's structural advantage

Most of these tools must run a cloud backend because their source data lives on their servers. Totem's data is already local in IndexedDB, so it can skip the backend entirely and write straight to the vault from the browser. That is a genuine edge: fewer moving parts, no server uptime to maintain, and nothing between the user's bookmarks and their vault.

The niche is narrow but real: people who keep X bookmarks and live in Obsidian. For them, a local-first, no-account, idempotent writer is strictly better than any cloud round-trip — it keeps working even if Totem's servers never exist.

The Omnivore cautionary tale

Omnivore's Obsidian plugin pulled from the Omnivore cloud API. When the company wound down and the API went offline, the plugin stopped working and users' sync broke — the notes they had were fine, but no new ones could arrive and the integration was dead. The lesson is direct: do not put Totem's servers on the critical path between a user's bookmarks and their vault. A local-file writer has no such dependency; it works as long as the browser and the folder exist.
