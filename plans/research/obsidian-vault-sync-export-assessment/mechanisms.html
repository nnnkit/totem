Six ways in, verified

Six mechanisms can move a bookmark into Obsidian. Each one's riskiest claim was handed to an independent skeptic to refute against primary sources. Only the File System Access API survives as a bulk-sync path.

Four corrections from the skeptics

The adversarial pass changed four specifics. None reversed the recommendation; each sharpened it.

  1. Directory permissions are per-session, not permanent. A stored directory handle survives in IndexedDB, but Chromium re-prompts for read-write permission on a new session. The connect flow must handle a quiet re-grant, not assume durable access.
  2. The URI length limit fails silently. Long notes over the URL cap don't error — they truncate or no-op. This alone disqualifies obsidian:// for body content of any size.
  3. The Local REST API is HTTPS with a self-signed cert. The extension would have to accept an untrusted cert on localhost, which is friction and a security conversation. Keep it strictly opt-in.
  4. The action popup can't host the picker. showDirectoryPicker() needs a full document with a user gesture; the extension's new-tab override page qualifies, the toolbar popup does not. The connect flow must live on the new-tab page.

Local or cloud?

Obsidian's own model is local-files-first; its paid Sync service layers a remote vault behind the local one. Totem should target the local vault and let the user's existing sync move the files.
