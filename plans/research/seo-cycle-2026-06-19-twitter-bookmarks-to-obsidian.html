Pair that thesis with a clean single-tweet-vs-whole-library fork and an honest fidelity caveat, then position Totem accurately as a local-first, session-route bulk exporter whose Markdown is vault-ready by unzip — explicitly not a one-click vault sync.

The Thesis (and why it's contrarian)

Every ranking page sorts these tools by features: threads, images, tags, YAML. None sort by the one variable that predicts survival — how the tool talks to X. A clean natural experiment already sits in the results:

The official API · fragile

kbravh's still-#1 plugin and the bulk Python pipelines all ask Twitter's API for permission. That route was paywalled April 27, 2023; the free tier can no longer read tweets. These are the tools that died or now cost money.

Your own session · durable

The survivors read what the logged-in browser already loaded — no key, no plan. prinsss (created after the break, 2,552 stars), X Bookmarks Sync ("No API key. No OAuth. Just your existing browser session"), and Totem all live here.

A third-party relay · it depends

tweet.md and the Post Embed plugin avoid the official API via public proxies (FxTwitter / oEmbed). Keyless and easy, but the fetch runs on someone else's server — a different fragility. Fine for one tweet.

The deeper payoff is archival, not PKM: once a tweet is plain-text Markdown in a vault, deletion stops mattering — and the API route literally cannot fetch a deleted tweet, so the "proper" path can't even do the thing archiving is for. The durable connection method and the archival goal are the same point from two directions.

Fact-Check Corrections Applied

Two adversarial verifiers ran against the survey's load-bearing claims. Every must-fix below was honored in the published post:

  • kbravh is dormant, not "maintained." Last release Dec 2022, last commit May 2023. The post calls it dormant — which strengthens the thesis rather than weakening it.
  • 0xrusowsky is abandoned (Feb 2023), not "alive." Presented as a dead 2023 project, used as the dated counter-example to prinsss.
  • X Bookmarks Sync version is 1.2.1, not "v1.1.10." The 1.1.10 string only appears in the community directory and conflicts with GitHub releases. Post cites no false version and uses the verbatim "No API key. No OAuth. Just your existing browser session."
  • X/Twitter Post Embed is a relay, not a browser-session tool. It fetches via FxTwitter/oEmbed, not the user's cookies. The post puts it in the third "relay" category — load-bearing for a connection-method thesis.
  • Thesis softened to "depends on the paid official API = fragile" vs "avoids it = durable." Not a clean "API = dead, session = alive": deriqsocial uses the API and is recently active (just gated), and relays avoid the API without using your session. The three-card framing captures this honestly.
  • One keep.md quote was a misattributed composite. Only "This is the path that actually survives a tweet getting deleted, because the content lives in a second place you control." is genuine; the "developer routes only return non-deleted tweets" sentence is NOT on keep.md. The post states the deleted-tweet/API point as its own reasoning, not as a keep.md quote.
  • No specific Twitter API dollar figure asserted. As of Feb 2026, X closed flat Basic/Pro tiers to new signups (pay-per-use default), so the post says only that the free tier can't read tweets and a paid plan is required.

SERP Gaps This Post Owns

  • Connection method as a survivability predictor — no competing page frames it; every guide ranks by features.
  • Single-tweet vs whole-library fork — the two intents collide on the same keywords and every incumbent blurs them.
  • Honest fidelity caveat — threads, quote tweets, long text, images, video round-trip differently; nobody tabulates it.
  • "Obsidian-ready" ≠ "works with Obsidian" — a folder of .md vs YAML-as-Properties that Dataview can query.
  • The archive doesn't contain bookmarks — the canonical reason the whole tool category exists, usually buried.
