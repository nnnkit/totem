Totem release research

Knowledge Digests and Sync Destinations

A next-release plan for turning Totem's local X / Twitter bookmark library into useful digests, then expanding into Obsidian, Notion, Sheets, Zotero, and Readwise style sync workflows.

Date: June 5, 2026
Audience: Totem product and engineering planning
Status: Research brief. No implementation committed.

Executive Decision

Ship a local-first digest layer first, then one destination that works without a backend: Obsidian Markdown sync. Treat Notion, Google Sheets, Zotero, Readwise, scheduled email, and AI summaries as paid/cloud features once the digest workflow proves value.

What users want

Not another export button. They want forgotten bookmarks to come back as useful reading, writing, research, and content creation material.

Totem advantage

Totem already has local bookmarks, full-thread hydration, reader state, search, highlights, and Markdown export. The fastest path is to compose these into digests.

Monetization path

Keep local digest and manual Obsidian sync free. Charge for recurring cloud sync, scheduled delivery, OAuth integrations, and AI organization.

What TweetSmash Teaches Us

TweetSmash's positioning is broader than bookmark backup. Its homepage sells "knowledge digests", AI search/chat, scheduled recipes, reading-time based digest creation, labels, thread/reply organization, and knowledge-base sync. Its resources page groups education around organizing, searching, managing, folders, auto-organization, PDF export, Notion export, and Sheets export.

Pattern Observed value Totem interpretation
Scheduled digests Bookmarks return at a deliberate reading or writing time. Start with manual "make digest" before adding schedule/email.
Recipes Topic, author, keyword, recent-bookmark, and content-inspiration filters. Use saved searches and reading budget as the first recipe system.

Competitive Notes

The market is converging around three jobs: find saved posts, organize them into reusable collections, and push selected knowledge into another system. Totem should not copy the whole surface. It should own the local-first, calm-reading, high-trust workflow and expand outward through sync adapters.

Destination Feasibility

Destination First version Technical requirement Business fit
Obsidian Free local Write Markdown to a user-selected vault folder via File System Access. Best first sync. No backend. Strong local-first alignment.
Markdown digest copy Free local Use existing Markdown export renderer and clipboard/download flows. Immediate proof of value and fallback for every destination.
Notion Paid cloud Public OAuth connection, server-side code exchange, token storage, database mapping. High willingness to pay. Should wait until sync model is stable.
Google Sheets Paid cloud Google OAuth scopes, spreadsheet create/append/update, rate handling. Useful for power users, analytics, and agencies.
Zotero Paid cloud API key or OAuth, item templates, write requests, duplicate detection. Useful for researchers. Best after links/papers detection improves.
Readwise Reader Paid cloud User API token or OAuth-like flow if available, save document endpoint, rate handling. Good fit for read-later users, but less core than Notion/Obsidian.
Email digest Paid cloud Account, scheduler, queue, mail provider, unsubscribe/compliance handling. Strong recurring value and natural paid conversion trigger.

Important constraint

Proper Notion public sync is not a pure extension feature. Notion public connections use OAuth and require exchanging the authorization code for an access token with a client secret. That belongs on a server, which makes Notion a later cloud-backed feature rather than the first local release.

Release Shape

Phase 0

Define the digest and sync model

Add a product spec before implementation. Define digest inputs, output format, destination adapter interface, idempotency rules, and sync state.

  • Digest inputs: saved search, tab, time range, reading budget, unread/read state, pinned items.
  • Digest output: title, generated date, bookmark list, source links, Markdown body, optional HTML preview.
  • Sync state: destination, last synced at, row/file ids, errors, retry status.
Phase 1

Ship manual local digests

Let users create a useful digest without AI or cloud accounts. This proves the workflow while staying close to Totem's current local architecture.

  • Add "Create digest" from the reading/search surface.
  • Offer 5, 15, 30, and 60 minute reading budgets.
  • Render as Markdown with source URLs and author metadata.
  • Support copy Markdown and download Markdown.
Phase 2

Add Obsidian Markdown sync

Let users choose their Obsidian vault folder, then write generated notes into a Totem-owned folder. This is the first real sync destination.

  • Write to Totem/Index.md, Totem/Digests/, and Totem/Bookmarks/.
  • Use stable filenames based on bookmark id and digest date.
  • Store a Totem manifest so cleanup only touches files Totem created.
  • Fallback to ZIP/Markdown download if directory access is unavailable.
Phase 3

Prepare paid cloud sync

Build account and entitlement foundations only after users can feel the digest value locally. Then add Notion first because the demand signal is clearest.

  • Totem account and billing entitlement.
  • Server-side OAuth token exchange and encrypted token storage.
  • Background sync queue with retry and per-destination status.
  • Notion database template and mapping preview.
Phase 4

Add AI organization and scheduled delivery

Once digests and sync are stable, AI can classify, summarize, and route bookmarks. Scheduled email and auto-sync become the strongest recurring paid features.

  • AI labels and digest summaries.
  • Weekly and topic-specific email digests.
  • "Ask my bookmarks" retrieval over local or cloud index.
  • Automatic Notion/Sheets/Readwise/Zotero routes by recipe.

Pricing Hypothesis

Tier Feature boundary Reasoning
Free Local bookmark reading, local search, manual digest, ZIP export, Markdown copy, manual Obsidian sync. Keeps trust high and makes the core workflow easy to adopt.
Pro Scheduled digests, Notion sync, Sheets sync, Readwise/Zotero sync, AI labels, AI summaries. These create ongoing server cost, OAuth maintenance, and repeated user value.
Team or creator Multiple destinations, shared collections, content workflow templates, higher sync limits. Useful later for creators, researchers, and agencies with repeat workflows.

Open Product Decisions

Digest surface Should digest creation live in Reading, Export, Search, or a new "Digests" tab?
Saved search dependency Should recipes be backed by saved searches first, or do we need labels before recipes?
Obsidian write scope Should sync only write generated digest notes, or also one Markdown note per bookmark?
Deletion semantics If a bookmark is removed from X, should Totem remove its Obsidian note or mark it unavailable?
Notion database shape Should Notion receive one page per bookmark, one row per bookmark, or digest pages that link out?
Payment timing Should Pro launch with Notion only, or wait until Notion plus scheduled email are both ready?

Immediate Next Steps

  1. Write a PRD for "Knowledge Digests and Sync Destinations" before code changes.
  2. Define a digest schema and destination adapter contract in plain TypeScript types.
  3. Prototype manual Markdown digest generation from existing bookmarks and cached details.
  4. Design the Obsidian folder output and sync manifest rules.
  5. Decide where the UI entry point belongs: Reading list, Export modal, or a new Digests view.
  6. Only after local digest + Obsidian is useful, plan Notion OAuth, server, and billing.
