Totem on Microsoft Edge

Launch analysis & readiness — should we publish on the Edge Add-ons store, and is it ready?

Prepared 2026-07-02 · scope: Edge Add-ons vs. Chrome Web Store, code compatibility, market reality, submission readiness

The verdict

Yes — launch on Edge. Treat it as a low-effort, low-cost secondary channel, not a growth bet.

It is a conditional yes, and the condition is already met: Totem is live on the Chrome Web Store. The same build works on Edge, registration is free, and the whole job is a few hours plus a manual upload. Just calibrate expectations — the Edge store will not send you users. It is a distribution endpoint you point people at, not a discovery engine.

01Will the same build work for both Edge and Chrome?

Yes — one identical ZIP, not two variants.

Edge is built on Chromium, so it reads the same Manifest V3 file and the same chrome.* APIs as Chrome. Totem's manifest has no Chrome-only fields, so nothing needs to fork. The one thing that used to differ — the in-extension "Review" button pointing at the Chrome Web Store — is now chosen at runtime via an isEdge() check, so a single dist/ / ZIP serves both stores.

Already compliant. Microsoft's two required certification changes — strip update_url and remove the word "Chrome" from the manifest name/description — were already satisfied. Totem's manifest has neither.

02Should you launch? The market reality.

Honest downside first: Edge store discovery is effectively dead.

Edge is the #2 desktop browser at roughly 13% desktop share (about 5% across all devices — but desktop is the only number that matters for extensions). Chrome sits near 63–65%. So the audience is real but far smaller, and the store behaves worse than the raw numbers suggest.

That last figure is the tell. A single Microsoft component — "Edge relevant text changes" — ships inside the browser and is counted as an install on every Edge install/update: 1.01 billion installs, and not one was a human choosing it. What it means in practice:

  • Topline install numbers are inflated by browser plumbing. If one auto-bundled component is 62% of the whole store, discretionary human-chosen installs are a much smaller pool than the headline suggests.
  • Organic discovery is weak. The reason one component can dominate is that the real long tail is thin — Edge users mostly don't install extensions, or install straight from the Chrome Web Store (Edge allows that).
  • So treat the store as a distribution endpoint, not a growth channel. Your installs will come from your own marketing pointing Edge users at the listing.

For scale context on the whole ecosystem: Chrome added 49,518 new extensions in a single quarter (Q2 2026) — more than Edge's entire ~30,636-item catalog. And more than half of Chrome's catalog has zero ratings, which cuts the other way in your favour (see next section).

03Why it's still worth doing

The cost is near zero and there are four concrete upsides.

  • $0 registration (Chrome charges a one-time $5), and the same ZIP — so it's a few hours of work, not a second build.
  • The "import on setup" channel. When someone sets up Edge and imports from Chrome, Edge only brings over a user's Chrome extensions that also exist on Edge Add-ons. Not publishing means those users silently lose Totem.
  • You stand out in a stale catalog. With 61.6% of Edge listings abandoned >1 year, an actively-shipped extension visibly reads as maintained. And since >half of Chrome's catalog has zero ratings, even 5–10 real reviews puts you ahead of most listings — leverage you can apply on both stores.
  • Legitimacy. A native Edge listing is a trust signal for Edge users who search for you.

05The one real risk

Review of aggressive permissions — the same risk you already cleared on Chrome.

Totem's sensitive behaviors — a MAIN-world mutation-hook.js that monkey-patches fetch/XMLHttpRequest, passive webRequest auth-header capture, and x.com bundle-fetching for GraphQL query IDs — draw reviewer scrutiny. Edge review is comparable-to-slightly-stricter than Chrome and takes up to 7 business days. But because Totem is already approved on Chrome, Edge approval is likely. Reuse the same written per-permission justifications, and keep the code unobfuscated (standard minification is fine).

08Optional, later

  • Website "Add to Edge" CTA. The marketing site has no browser detection today (every visitor sees "Add to Chrome"). Adding a browser-detected or dual CTA is a site-only change, worth doing once the Edge listing is live.
  • CI automation. The Edge Update REST API (v1.1; keys expire every 72 days) can automate package updates — but not the initial submission or metadata. A good fast-follow if Edge proves worth maintaining.
