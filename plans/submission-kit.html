Why it is not mature — paste if a notes field appears
Totem is not mature content. The extension itself has no sexual content, violence, strong language, drugs, alcohol, tobacco, gambling, ads, or adult links. It is a private reading queue for the user's own Twitter/X bookmarks. Those posts are shown only to the same user who saved them. Totem does not host a public feed, comments, chat, or sharing between users. Accessing X content requires the user's existing X account (X is 13+). Totem is not directed at children under 13.
Don't mark Mature just because a saved tweet could be anything. Chrome and Edge both say to consider user-generated content and linked pages, but Totem is not a social network: it only shows the user's own private library, and Edge policy §2.12.2 is satisfied by requiring a pre-existing X account. Same class as a read-it-later or RSS reader.

It turns your Chrome new tab into a calm reading queue for your Twitter/X bookmarks — a read-it-later for tweets, threads, and X articles — so the posts you save come back to you instead of vanishing. Most people bookmark tweets and never return. And opening X to "check your bookmarks" turns into twenty minutes of doom-scrolling. Totem fixes both: your saved posts wait for you on every new tab. No feed, no algorithm, no noise. 4Permission justifications Privacy page · one box per permission

The manifest declares five install-time permissions plus one host permission, and three optional permissions the user grants by turning a feature on. Totem's justifications are the same on both stores; only the two that name the browser swap.

storage justification · permissions
Stores bookmarks, tweet detail cache, reading progress, highlights, notes, runtime state, and user settings locally in the browser.
webRequest justification · permissions
Observes x.com GraphQL requests from the user's own browser session to capture the auth headers required to sync that user's bookmarks. Totem does not block or modify requests with webRequest.
declarativeNetRequest justification · permissions
Sets the required request header on Totem's own x.com GraphQL requests so they match the authenticated browser session. Rules are bundled in the extension (public/rules.json), not fetched remotely.
scripting justification · permissions
Registers or removes the optional "Open in Totem" content script on x.com when the user enables or disables that setting.
cookies justification · permissions
Reads the x.com session/account cookie locally to identify the active X account, scope the local bookmark cache, and detect logout or account changes.
https://x.com/* justification · host_permissions
Runs Totem's x.com content scripts and sync logic only on x.com so the extension can detect account context and keep the local bookmark library in sync.

Optional permissions — requested only when the user enables the feature

topSites justification · optional_permissions
Shows Chrome quick links on the new tab page only after the user enables Quick Links.
favicon justification · optional_permissions
Shows favicons for Quick Links only after the user enables Quick Links.
search justification · optional_permissions
Lets Totem submit a new-tab search to Chrome's default search engine only after the user chooses "Browser default".

Are you using remote code? → No

Manifest V3, everything bundled. The declarativeNetRequest ruleset ships at public/rules.json — one rule, setting Origin: https://x.com on Totem's own x.com GraphQL XHRs. Nothing is fetched and evaluated as code.

6Reviewer note Test-instructions field

Totem's MAIN-world hook, passive auth-header capture and new-tab override are what reviewers ask about. Saying it first, plainly, is what got it through Chrome; Edge review is a human pass and comparable-to-slightly-stricter on aggressive host behaviour.

Reviewer note — paste the whole block — chars
WHAT TOTEM DOES Totem replaces the new tab page with the user's own Twitter/X bookmarks, as a reading queue. It reads, searches, highlights, annotates and exports those saved posts. Everything is stored locally in the browser (IndexedDB and storage.local). There is no Totem account and no Totem server. TESTING THE EXTENSION We cannot supply a test account — Totem reads the reviewer's OWN x.com session, and a shared login would breach X's terms and trip its bot protection. 1. Sign in to x.com normally, with any account. If it has no bookmarks, bookmark two or three posts first. 2. Install Totem and open a new tab. The saved posts appear as a reading queue. 3. Click one to open the reader. Press / to search the library. Select text to highlight it. 4. Settings -> Export downloads the whole library as a ZIP (Markdown, CSV, JSONL). NEW TAB OVERRIDE - DISCLOSED Totem sets chrome_url_overrides.newtab. The browser shows its own one-time "an extension changed your new tab page" prompt, and the change is reversed by disabling or removing the extension. The takeover is stated plainly in the listing description, under "EVERY NEW TAB IS YOUR READING QUEUE". THE THREE BEHAVIOURS THAT USUALLY DRAW QUESTIONS 1. MAIN-world content script (content/mutation-hook.js). Runs on x.com at document_start and wraps fetch and XMLHttpRequest. It reads only the x.com GraphQL calls the page itself makes, for two reasons: to notice when the user bookmarks or unbookmarks a post on X so the local library stays in step, and to learn the GraphQL query ids x.com is currently using. It does not modify requests or responses, does not run on any other origin, and sends nothing off-device. 2. Passive auth-header capture (webRequest, observational only - never blocking). Totem reads the authorization, cookie and CSRF headers the browser is already sending to x.com from the user's own signed-in session, so that Totem's own bookmark requests to x.com are authenticated as that user. The headers stay on the device, are refreshed from the live session rather than archived, and are never sent anywhere except back to x.com. 3. GraphQL query-id discovery. x.com rotates the query ids on its own endpoints. Totem resolves them in this order: a catalog built passively from real x.com traffic, a 10-minute in-memory cache, and only as a fallback, reading x.com's own JavaScript bundle. Every step targets x.com and nothing else. NO REMOTE CODE Manifest V3, everything executable ships inside the package. The declarativeNetRequest ruleset is bundled at public/rules.json and contains exactly one rule: set Origin: https://x.com on Totem's own x.com GraphQL XHRs so they match the authenticated session. Nothing is fetched and evaluated as code. DATA AND NETWORK Bookmarks, tweet cache, reading progress, highlights, notes and runtime state live in the browser's IndexedDB and storage.local. Theme and preference values use storage.sync, which is the browser's own sync, not a Totem service. There is no analytics and no telemetry. Totem itself makes network requests to x.com only; "Send to Grok" opens grok.com in a tab when the user clicks it, which is an ordinary navigation. OPTIONAL PERMISSIONS topSites, favicon and search are optional and are requested only when the user turns on Quick Links or chooses "Browser default" as the new-tab search engine. A fresh install holds none of them. PRIVACY POLICY https://usetotem.xyz/privacy
