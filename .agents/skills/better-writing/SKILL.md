# Better Writing

This is a Totem-specific writing skill. Its job is to keep the agent disciplined:
small context, one phase at a time, human judgement before polish.

## Start

1. Read `plans/blog-pipeline.md`.
2. Load only the relevant post packet or draft file.
3. State the active phase before working.
4. Do not mix phases unless the user asks.

Use `plans/blog-drafts/NN-slug.md` for drafts. Prefer this shape:

```md
## Post Packet
## Fragments
## Beat Map
## Draft
## Editorial Notes
```

## Context Rules

- Work from one draft file at a time.
- Keep the active context under the current phase plus the blog voice.
- Do not pull unrelated repo context unless the post needs product facts.
- If context feels bloated, ask to restart from the draft file and current phase.
- Prefer concrete facts, dates, links, screenshots, and examples over broad claims.

## Phase 1: Fragment Grill

Use when the idea is loose.

Do:
- collect disconnected fragments
- pull out sharp lines in Totem's voice
- list objections, missing facts, and overclaim risks
- identify what the post is not allowed to say
- ask pointed questions when the human needs to supply judgement

Do not:
- write an intro
- create a full outline
- smooth the fragments into generic prose

## Phase 2: Beat Map

Use when there are enough fragments to find a path.

Produce:
- one reader problem
- one thesis
- 5-8 beats, each with a job
- source needs per beat
- where Totem appears, usually late
- what the post explicitly does not cover

Do not draft full prose in this phase.

## Phase 3: Draft Beat

Write one beat at a time.

After each beat, check:
- Does it sound like Totem?
- Is it specific?
- Is it true?
- Is it terse?
- Did it avoid promotion until earned?

If the beat fails, rewrite it before moving on.

## Phase 4: Editorial Pass

Only after the draft basically works:

- add subheads
- add internal links
- verify source links and claims
- cut repeated points
- remove SEO scaffolding
- make the CTA small and honest
- prepare frontmatter

If the post reads like a feature announcement, push it back to Beat Map.

## Output Style

Be direct and demanding. Do not praise weak writing. Name the exact sentence,
beat, or claim that fails and why. Preserve good human fragments instead of
rephrasing them into generic SaaS copy.
