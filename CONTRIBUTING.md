# Contributing

## Tracking work

All work — features, bugs, ideas, chores — is tracked in **GitHub issues**, not in local files. Do not add planning, PRD, or status-tracker markdown to the repo; open an issue instead.

- **Feature / idea:** open an issue with the *Feature / idea* template.
- **Bug:** open an issue with the *Bug* template.

## Where things live

- **Code:** `src/` (extension), `apps/site/` (marketing site).
- **Living docs:** `docs/` — reference docs, the screenshot workflow, the blog/SEO process docs, and `docs/solutions/` patterns. See [`docs/README.md`](docs/README.md).
- **Domain vocabulary:** `CONCEPTS.md`.
- **Architecture:** `ARCHITECTURE.md`.
- **Release + publish:** `RELEASING.md` (GitHub release), `PUBLISH.md` (Chrome Web Store).

Keep the repo minimal. If a document is a tracker or a finished plan, it belongs in an issue or in git history — not on disk.
